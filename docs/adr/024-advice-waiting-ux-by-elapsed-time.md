# ADR 024: AI提案の生成待ち表示は経過時間で切り替える(APIは変更しない)

## ステータス
決定済み

## 背景
フェーズ9-4として、AI提案の読み込み中の表示を改善する。現状は「AI提案を確認中...」の一行のみで、
次の2点がユーザーに伝わらなかった。

1. 待ち時間の見通し: キャッシュ返却なら1秒以内だが、新規生成はAI API呼び出しを含み実測10〜30秒
   かかる(タイムアウト時の最悪値は、天候API10秒+AI API60秒が直列に実行されるため約70秒)。
   どちらなのか区別できず、固まったように見える
2. 内容が変わらない理由: `GET /advices/latest`は前回生成から24時間以内ならキャッシュを返す
   (docs/adr/004)ため、「最新のAI提案を確認する」を押しても同じ提案が出る

キャッシュ返却か新規生成かの判定はBE(service層)で行っており、FEはレスポンスが返るまで知る手段がない。

## 検討した選択肢
- **A: FEのみ。読み込みが一定時間(3秒)を超えたら「新しいAI提案を生成しています」に切り替える**:
  API変更なし。推測なので、BEのコールドスタート等で遅いだけのキャッシュ返却でも「生成中」と出うる
- **B: A + `LatestAdviceResult`に生成/キャッシュの区別(`generated`フラグ)を追加する**:
  完了後に「今回新しく生成しました」等を正確に出せる。ただしAPI・docs/api.mdの変更が必要で、
  「待っている最中」の表示には使えない(応答が返るまで分からないのは同じ)
- **C: 判定用と生成用にエンドポイントを分ける**: 待つ前に区別できるが、GETに副作用を持たせて
  1リクエストで完結させた既存設計(docs/adr/004、CLAUDE.mdルール5)を崩すため不採用

## 決定
Aを採用する。あわせて、`status: ready`の提案の下に「前回の生成から24時間が経つまでは新しく
生成されず、同じ提案が表示されます」という補足を常に表示する。「1日1回」とは書かない
(実際は24時間経過後の最初のアクセスで生成されるため、数日空けば間の日には生成されない)。
また、記録件数が3件未満・有効な目標なしの場合は生成が起こらないため、遅くても「生成中」とは出さない
(Dashboardが`canGenerate`を渡す)。

## 理由
1. 課題の本体は「待っている最中に何が起きているか分からない」ことで、ここはBにしても解決しない。
   Aだけで主な不満(固まって見える)は解消できる
2. 「内容が変わらない理由」は、生成/キャッシュを判別しなくても仕様(24時間に1回)を常に書いておけば伝わる
3. Bは完了後の表示が正確になる利点があるが、API変更の手間に見合わない。必要になった時点で追加できる
   (レスポンスへのフィールド追加は後方互換)

## 影響
- `frontend/src/components/AdviceView.tsx`に`SLOW_THRESHOLD_MS`(3秒)と`slow`のstateを追加
- 「生成中」表示は推測のため、遅いだけのキャッシュ返却でも出ることがある。文言は断定を避け
  「30秒ほど、長いと1分以上かかる場合があります」とした
- API・DBの変更なし
