# ADR 025: Geminiのモデルをフォールバック構成にする(混雑・無料枠超過対策)

## ステータス
決定済み

## 背景
2026-10-13、本番で`GET /advices/latest`が500を返し続けた(10回以上、時間帯を問わず)。
Railwayのログとローカルでの再現確認から、原因はPacelyのコードやRailwayのプラン変更ではなく、
使用モデル`gemini-3.6-flash`がGoogle側で503(`This model is currently experiencing high demand`)を
返していたことと判明した。同じAPIキーで他のFlash系を試した結果は次のとおり(2026-10-14実測)。

| モデル | 結果 |
|---|---|
| gemini-3.6-flash(それまでの設定) | 503 混雑 |
| gemini-3.7-flash / 3.8-flash / flash-latest | 503 混雑 |
| gemini-3.5-flash | 429 無料枠のクォータ超過 |
| gemini-2.5-flash | 404 廃止済み |
| gemini-3.1-flash-lite | 200 成功 |

それまでは単一モデル固定で、503を受けると即失敗していた。有料ティアへの変更は費用面から
今は行わず、無料枠のままで乗り越えたい。

## 検討した選択肢
- **A: 単純に別のモデルへ固定で切り替える(gemini-3.1-flash-liteのみ)**: 一行で済むが、
  そのモデルも混雑・廃止されたとき同じ問題が再発する。提案の質が下がる側に常に固定される
- **B: 同じモデルで待ってリトライする**: 今回のように数十分〜長時間続く混雑には効かない
- **C: モデルの優先順位リストを持ち、503/429のときだけ次のモデルを試す(採用)**
- **D: 有料ティアにする**: 確実だが費用が発生する。現時点では見送り(下記)
- **E: 提供元ごと変える(Claude/OpenAI)**: ADR-002・012の抽象化(`AdviceGenerator`)で可能だが、
  モデル比較を含む別タスク。今回の復旧には大きすぎる

## 決定
Cを採用する。`geminiModels`の先頭(`gemini-3.6-flash`)から順に試し、「そのモデル固有の失敗」の
場合のみ次(`gemini-3.1-flash-lite`)へ切り替える。

- 切り替える対象は429(クォータ超過)・503(混雑)・500/504(一時的なサーバー側の失敗)・
  404(モデル廃止。gemini-2.0-flash・2.5-flashで実際に起きた)。400・認証エラー・通信失敗・
  タイムアウトは別モデルでも直らない/待ち時間が倍になるため、切り替えずに失敗させる
- 各モデルのタイムアウト(60秒)とは別に全体の上限(90秒)を設け、切り替えで待ち時間が倍に
  ならないようにする。リクエストが中断された場合は次のモデルを呼ばない
- APIキーはURLのクエリ(`?key=`)ではなく`x-goog-api-key`ヘッダーで渡す。URLに入れると、
  リクエスト作成・送信の失敗時にエラー文へキーが混ざる経路が残るため
- 全モデルが断った場合は`ErrExternalAPI`(従来どおり定型メッセージで500)
- 予備モデルで生成した場合はログに`generated with fallback model`を残す。どのモデルで
  生成したかはDBには保存していない(必要になったら`advices`にカラム追加を検討)

## 理由
1. 無料枠のモデルは混雑・上限超過・廃止が日常的に起きるため、単一モデル固定では止まりやすい
2. 質の高いモデルを通常は使い、断られたときだけ軽量モデルに落とせば、質と可用性を両立できる
3. 変更は`ai_client.go`に閉じ、`AdviceGenerator`インターフェースやservice層は変わらない

## 今後の課題
- メインが200で空の応答・不正なJSON(安全フィルタによるブロック等)を返した場合は、現状
  予備モデルへ切り替えない。実際に起きていないため見送ったが、予備(lite)側が不正な出力を
  返しやすい可能性もあり、発生したら応答の解析まで含めて切り替える設計に広げる
- どのモデルが生成したかをDBに残していない(影響の項参照)

## 影響
- `GeminiClient`に`baseURL`を追加し(テストでhttptestに差し替えるため)、HTTP呼び出しを
  `callModel`に切り出した。単体テスト`ai_client_test.go`を追加(切り替え・全滅・非切り替えの4ケース)
- **提案の質**: 予備のgemini-3.1-flash-liteで生成された提案は、メイン(3.6-flash)より質が
  劣る可能性がある。実API(2026-10-14)では、日本語の自然さ・メニューの妥当性は実用範囲に見えたが、
  フルマラソン目標に対し15km@7:00/kmのジョグ、という保守的な提案だった。継続して様子を見る
- **履歴で比較できない**: どのモデルの提案か記録していないため、質の違いを後から追えない
- **有料ティアは未実施**: 無料枠のままでは、全モデルが同時に混雑・上限になると提案は生成できない。
  その場合は有料ティア(D)か提供元の見直し(E、ADR-002の再決定)を検討する
