# ADR 003: 体感的きつさ(RPE)にBorg CR10スケール(1〜10)を採用

## ステータス
決定済み

## 背景
ランニング記録の入力項目として、距離・時間・日付に加え、AIへの提案精度を上げるための主観的なデータを入れるかどうかを検討した。心拍数はデバイス連携なしでは意味のある値が取れないため見送り、代わりに主観的運動強度(RPE)の採用を検討した。

## 検討した選択肢
- **心拍数**: 手入力では実用的な精度が出ない(走行中の平均心拍数を人が記憶して入力するのは非現実的)。デバイス連携(COROS等)が前提になるため今回は見送り
- **RPE: Borgオリジナルスケール(6〜20)**: 心拍数(÷10)と対応するように設計された指標。心拍数データを扱わないPacelyでは対応させる意味がない上、範囲が直感的でない
- **RPE: Borg CR10スケール(1〜10)**: 心拍数との対応を前提とせず、直感的なわかりやすさを重視した指標。市民ランナー向けアプリ・デバイスで広く使われている
- **COROSの3段階方式**: リアルタイムでのデバイス操作を前提とした簡易区分。データの解像度が低い

## 決定
runsテーブルにRPE(1〜10、nullable)を追加する。スケールはBorg CR10を採用する。

## 理由
1. 心拍数と対応させる必要がないため、6〜20スケールを採用する理由がない
2. Pacelyは「運動後にゆっくり記録する」想定のため、COROSのような3段階のリアルタイム簡易入力である必要がなく、10段階での解像度の高いデータ取得を優先できる
3. 同じペース・距離でもRPEの違いから疲労蓄積の兆候をAIが判断材料にできる

## 影響
- 将来的に心拍数データ(COROS等のデバイス連携)を扱うようになった場合、心拍数とRPEの相関を見る機能を追加する余地がある
