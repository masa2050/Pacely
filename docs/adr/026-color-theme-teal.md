# ADR 026: 配色をティール系に統一し、色・角丸・影をトークンで管理する

## ステータス
決定済み

## 背景
フェーズ9-3「全体的な配色の設定・統一」。着手時点の配色は、Viteの初期テンプレートの既定値
(紫`#aa3bff`、ファビコンもViteのロゴ)がそのまま残っていた。就活でアプリを直接見せる機会が近く、
テンプレートのままと分かる見た目は避けたい。

調査の結果、色はほぼ`index.css`の変数で管理されており(App.cssの`var(--…)`参照は59箇所)、
直書きはエラーの赤・評価ボタンの緑/赤のみだった。一方で、カードは枠線のみでページと同じ背景色のため
平板に見え、角丸は6px/8pxが混在し、ボタンにホバー時の変化が無かった。

## 検討した選択肢

### 範囲
- **A: 色の変数を差し替えるだけ**: 最速だが、カード・ボタンの細部はばらついたまま
- **B: 色に加えて、意味の色(エラー・成功)の変数化、テンプレートの名残の削除、角丸・影・ホバーの統一(採用)**
- **C: Bに加えてWebフォント導入・文字サイズ体系・余白の刷新**: 変化は最大だが、画面ごとの確認が増えて重い

### アクセント色
- ティール/グリーン系(採用) / オレンジ系 / ブルー系 / 紫のまま調整

## 決定
- 範囲はB、アクセント色はティール系とする
- ライト: アクセント`#0b7d6e`、ページ背景`#f5f8f7`(わずかに色付け)、カード`#ffffff`
- ダーク: アクセント`#2cc4ad`、ボタンの文字は白ではなく濃い色(`--on-accent: #08201c`)
- 色・角丸(`--radius-sm` 8px / `--radius-md` 12px)・影(`--shadow-card`)はすべて`index.css`の
  変数で定義し、App.cssに色を直書きしない
- カードは白(`--surface`)+薄い影で、ページ背景から浮かせる
- ボタンのホバーは、背景色の差し替えではなく半透明の色(`--hover-overlay`)を背景画像として重ねる
- ファビコンをViteのロゴから、ティールの角丸四角+二重シェブロン(前へ進む=ペース)に変更

## 理由
1. ティールは健康・持続・屋外のランニングを連想させ、「AIコーチ」の落ち着いた信頼感とも合う。
   大手ランニングアプリに多いオレンジ系と被らない
2. アクセント色は、白文字とのコントラスト比が基準(WCAG AA: 4.5以上)を満たす濃さを計算して選んだ。
   最初の候補`#0f9d8a`は3.38で不足したため、`#0b7d6e`(5.03)にした。ダークの明るいティールは
   白文字だと2.19で読みにくいため、濃い文字(7.79)にした
3. ホバーで背景色を差し替えると、同じセレクタに含まれる透明なボタン(編集アイコン・戻るボタン等)まで
   塗りつぶされてしまう。重ねる方式なら、塗りのボタンも透明なボタンも自然に反応する
4. 変数で一元管理しておけば、今後の色の微調整は`index.css`だけで済む

## 影響
- `frontend/src/index.css`: 色トークンを全面的に差し替え、`--surface`・`--danger`・`--success`・
  `--on-accent`・`--hover-overlay`・`--radius-*`・`--shadow-card`を追加。テンプレートの名残
  (`--code-bg`・`--social-bg`・`--mono`・`code`/`.counter`/`#social`のスタイル)を削除
- `frontend/src/App.css`: 直書きの色・角丸を変数に置換、カード/履歴一覧に背景と影、ボタンのホバーを追加
- `frontend/public/favicon.svg`を差し替え、`index.html`の`lang`を`ja`に修正
- フォント・余白・レイアウトは変えていない(範囲C)
