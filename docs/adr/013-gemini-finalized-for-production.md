# ADR 013: 本番AI APIもGeminiを継続利用(ADR 002の再評価を確定)

## ステータス
決定済み(ADR 002「本番移行時に再評価予定」を確定させる形での更新)

## 背景
ADR 002で、開発初期はGemini APIの無料枠を使い、本番リリース前にClaude/OpenAIとの品質比較のうえで
最終的なAPIプロバイダを再決定する、としていた。フェーズ6(デプロイ)を進めるにあたり、この再評価を行った。

## 検討した選択肢
- **Claude/OpenAIへの移行**: 継続的な無料枠が無く、クレジットカード登録・プリペイド課金が必要になる
- **Geminiを本番でも継続利用**: クレジットカード未登録のまま無料枠内で運用を続けられる。ただし無料枠の
  利用規約上、送信データ(練習記録・目標などのプロンプト内容)がGoogleのサービス改善に利用される制約がある

## 決定
本番環境でもGemini APIを継続利用する。ADR 012で実装済みの`AdviceGenerator`インターフェース抽象化は、
将来プロバイダを変更する可能性に備えてそのまま維持する。

## 理由
1. クレジットカードを登録していないため、無料枠の範囲を超えて意図せず従量課金が発生する心配がない
   (Claude/OpenAIはプリペイド課金前提のため、この安心感が得られない)
2. 個人開発MVPかつ低トラフィック想定のため、無料枠のレート制限内で十分に運用できる見込み
3. データがGoogleのサービス改善に利用される点は、プライバシーポリシー・利用規約に明記して
   ユーザーに開示することで対応する方針とする(隠さず開示する、という前提での許容)

## 影響
- プライバシーポリシー・利用規約(フェーズ6のタスク)には、「AI提案生成のためにGemini APIへ練習記録・
  目標データを送信すること」「無料枠利用のため送信データがGoogleのサービス改善に利用され得ること」を
  明記する必要がある
- フェーズ6の「AI APIの利用上限(spending limit)設定」は、Geminiの無料枠には従量課金の概念が
  無いため、Anthropic/OpenAIのような金額ベースの上限設定ではなく「無料枠のレート制限を超えた場合の
  挙動確認(429エラー時にdocs/api.md 4.の500として扱われるか)」に読み替える
- 将来トラフィックが増え無料枠で不足する場合、または品質面で不満が出た場合は、ADR 012の抽象化を
  使って有料プロバイダへ切り替える(ADR 002の想定通り、影響範囲はAdviceGenerator実装の追加のみ)
