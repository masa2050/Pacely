# ADR 002: 開発初期のAI APIにGeminiを採用(本番前に品質比較)

## ステータス
決定済み(本番移行時に再評価予定)

## 背景
PacelyのコアであるAI提案機能(アドバイス・練習メニュー生成)に使うAI APIを決める必要があった。Claude API、OpenAI API、Gemini APIを比較した。

## 検討した選択肢
- **Anthropic Claude API**: 恒久的な無料枠がなく、新規登録時の少額試用クレジットのみ。それ以降は完全プリペイド課金
- **OpenAI API**: 現在、新規アカウントへの無料クレジット付与がほぼ廃止されており、最初から課金前提
- **Google Gemini API**: 3社の中で唯一、期限のない継続的な無料枠(Flash系モデル、リクエスト数上限あり)が存在する

## 決定
開発・プロトタイピング段階ではGemini APIの無料枠を使用する。本番リリース前に、Claude/OpenAIとの出力品質(練習メニューの妥当性、プロンプトへの追従性)を比較し、最終的なAPIを再決定する。

## 理由
1. 個人開発の初期段階でAPI費用を発生させずにプロンプト設計の試行錯誤ができる
2. architecture.mdの設計上、AI呼び出しをバックエンドのservice層に閉じ込めているため、後からAPIプロバイダを変更しても影響範囲が限定的
3. マラソン練習メニュー生成は、複雑な推論よりも一般的なトレーニング原則+個人データの組み合わせが中心のため、軽量モデルでも一定の実用性が見込める

## 注意点
- Gemini無料枠は入力データがGoogleのサービス改善に利用される規約のため、本番運用(実際のユーザーデータを扱う段階)では有料ティアへの切り替え、またはClaude/OpenAIへの移行を検討する
