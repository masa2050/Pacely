# ADR 020: AI提案履歴を1行サマリーの一覧にし、専用画面へ移す

## ステータス
決定済み(実装は未着手。フェーズ9-5)

## 背景
ダッシュボードの「過去の提案履歴を見る」は、押すとAI提案カードをそのままの形で
縦に積んで表示する。提案は1日1件生成されるため件数が増え続け、カードが下へ
無限に伸びてダッシュボードのレイアウトが崩れる。

ランニング記録では同じ問題に対し「`max-height: 360px` + 縦スクロール」で対処済み
(カードの中だけをスクロールさせ、ダッシュボード全体は伸ばさない)。提案履歴にも
同じ方式を当てるかどうかが論点になった。

### 実測: 1件あたりの高さが記録と2桁違う

この判断を決めたのは以下の実測値(PC3カラム表示・カード幅356pxで計測)。

| 対象 | 1件あたりの高さ |
| --- | --- |
| ランニング記録(テーブルの1行) | 約34px |
| AI提案カード1件 | 約570px |

提案カード1件 ≒ 記録17行分。記録一覧で縦スクロールがうまく機能しているのは、
360pxの枠に10行以上が一望できるからであり、同じ枠に提案を入れても**1件すら
収まらない**(570pxの2/3が見えるだけ)。なお570pxのうち約150pxはフェーズ7-5で
追加したフィードバックUI(コメント欄が常時展開)が占めている。

## 検討した選択肢

- **A: ランニング記録と同じ縦スクロール(max-height + overflow-y)**
  実装は最も簡単で既存パターンとも揃うが、上記のとおり枠内に1件も収まらず、
  狭い枠の断片を延々スクロールする形になる。「ダッシュボードを伸ばさない」という
  目的も、600px以上に広げないと果たせず中途半端
- **B: 1件ずつ表示し、左右の矢印で切り替える(カルーセル)**
  高さは固定できるが、「先週の提案」を探すのにクリックを繰り返す必要があり、
  全体で何件あるかも掴みにくい。「見比べる・探す」という履歴の用途に合わない
- **C: 1行サマリーの一覧にし、クリックで全文を展開する**
  各件を「日付 / メニュー(距離・ペース) / 評価」の1行に圧縮する。
  1行あたり約34pxとなり、記録一覧と同じ構造・同じスクロール方式が成立する
- **D: 直近3件だけ表示し「もっと見る」で追加読み込み**
  最も簡単だが、押すたびにダッシュボードが伸びるため問題の先送りにしかならない
- **E: 履歴をダッシュボードから外し、専用画面へ移す**
  フェーズ7-2で追加済みのサイドバー(記録/目標/AI提案/設定)が受け皿になる。
  専用画面ならページ全体が縦に伸びるのは自然で、入れ子スクロールの窮屈さがない

## 決定
**CとEを併用する。**

- 履歴は「日付 / メニュー(距離・ペース) / 評価(👍・👎・未評価)」の1行一覧として表示し、
  行をクリックするとその件の全文(アドバイス本文・note・天候・フィードバック)を展開する
- 履歴はダッシュボードから外し、サイドバーから開く専用画面に移す。
  ダッシュボードのAI提案カードには「本日の提案」のみを残し、
  「過去の提案履歴を見る」ボタンは履歴画面への導線に変更する
- `GET /advices`は現在LIMITが無く全件返す(1日1件生成なので1年で365件、
  それぞれ200字の本文付き)。一覧に必要なのは日付・メニュー・評価だけだが、
  本文を除いた一覧専用のレスポンスを別に作るのはMVPに対して過剰なため、
  **既存のエンドポイントに件数上限(直近50件程度)を付けるに留める**。
  それ以上の遡りが必要になった時点でページングを検討する

## 理由
1. **高さの問題を回避ではなく消滅させている**。A・Bは「1件570px」を前提に工夫する案だが、
   Cはその前提自体を変える。結果として、既に作って機能しているランニング記録と
   同じスクロール方式が、今度は正しく機能する
2. **履歴の用途に合っている**。過去の提案を開くのは「一覧して傾向を掴む」ためであり、
   全文を順に読みたいわけではない。全文が必要なのは特定の1件だけで、それは展開で足りる
3. **フェーズ8(AI提案の質の改善)に直結する**。「毎回同じ練習メニューが提案される」問題は、
   `10km / 5:40/km`が縦に並ぶ1行一覧にすると一目で分かる。8-2の改善前後を
   比較する画面としてそのまま使える
4. **フェーズ7-5のフィードバックが画面上で意味を持つ**。一覧に評価列を置くことで、
   貯めたis_helpfulが「保存して終わり」ではなく振り返りに使われる
5. 履歴は一目で見たい情報ではなく振り返りたいときに開く情報のため、
   ダッシュボードに常駐させる必要がない(E)

## 影響
- FE: AI提案履歴の専用画面を追加する。ルーティングライブラリは引き続き導入せず、
  App.tsxの画面切り替え(PrivacyPolicyと同じ方式、docs/adr/015)に従う
- FE: `AdviceView`から履歴表示の責務を外す。ダッシュボードのAI提案カードは
  「本日の提案」表示に専念する
- BE: `GET /advices`(`repository.ListByUser`)に件数上限を追加する。
  `docs/api.md`の記載も更新する
- 一覧行に出すメニュー要約は`next_menu`の`distance_km`/`pace_sec_per_km`を使う。
  フェーズ8-2で`next_menu`にメニュー種別を追加した場合は、この列に種別も表示する
- カードの高さ約570pxのうち150pxを占めるフィードバックUI(コメント欄の常時展開)は、
  フェーズ9-2で「評価ボタンを押したらコメント欄が出る」形に見直す。これは本ADRとは
  独立に効く改善であり、展開後のカード表示にも効く
