# ADR 018: 地域(region)を47都道府県の選択式にする

## ステータス
決定済み

## 背景
天候取得用の地域(`users.region`)は自由入力のテキストフィールドで、入力値をそのまま
OpenWeatherMapの都市名検索(`q=`)に渡していた。OpenWeatherMapの都市名検索はローマ字
(英語表記)が前提のため、「東京」と日本語で入力すると引けず、ユーザーは「Tokyo」のような
ローマ字を自分で考えて入力する必要があった。これは分かりづらく入力の手間も大きい。

`docs/requirements.md`では元々「ユーザーが都道府県/都市を手動選択する方式にする」と
定めていたため、自由入力は要件に対しても中途半端な実装だった。

## 検討した選択肢

### 選択の粒度
- **A: 47都道府県のみ**: 選択肢が47件で済み、単一のセレクトボックスに収まる
- **B: 市区町村まで選択できるようにする**: 1900件超の選択肢、または「都道府県→市区町村」の
  2段階セレクトが必要になる

### 保存する値と変換場所
- **A: フロントエンドが都道府県名→ローマ字の変換を持ち、DBにはローマ字都市名を保存する**:
  バックエンドは無変更で済むが、OpenWeatherMap固有の検索キーワードがDBとフロントエンドに
  染み出す。プロバイダを変えると保存済みデータの意味が変わってしまう
- **B: DBには都道府県名(日本語)を保存し、OpenWeatherMap用キーワードへの変換はバックエンドの
  service層(OpenWeatherMap実装)で行う**: 「ユーザーが選んだもの」がそのまま保存され、
  外部API固有の事情はservice層に閉じ込められる(CLAUDE.md方針6、docs/architecture.md 7.)

## 決定
- 粒度はA(47都道府県のみ)を採用。`frontend/src/lib/prefectures.ts`に47件の配列を置き、
  設定画面の地域欄をテキスト入力からセレクトボックスに変更する
- 保存と変換はBを採用。`internal/service/weather_client.go`に
  「都道府県名→OpenWeatherMapの検索キーワード」の変換表(`prefectureToCity`)と
  `buildQuery`を追加し、`WeatherClient`インターフェースではなくOpenWeatherMap実装側に置く
- 検索キーワードには国コード`,JP`を付ける
- 変換表に無い値(7-3以前に自由入力で保存されたローマ字表記)は、そのまま天候APIへ渡す(後方互換)。
  既存データの一括変換(バックフィル)は行わない

### 実測で判明した例外2県
47都道府県名のローマ字表記を実際にOpenWeatherMapへ投げて確認した結果、45県はその県内
(県単位または県庁所在地)にヒットしたが、以下2県は同名の別地域にヒットした。
そのため変換表では県庁所在地を指定している。

| 都道府県 | 素直なローマ字 | ヒットした場所              | 変換表の値      |
| -------- | -------------- | --------------------------- | --------------- |
| 茨城県   | `Ibaraki`      | 大阪府茨木市(34.8N 135.6E) | `Mito`(水戸市) |
| 石川県   | `Ishikawa`     | 沖縄県うるま市石川(26.4N 127.8E) | `Kanazawa`(金沢市) |

## 理由
1. 天候情報の用途は「今日走るのに暑いか・雨か」という練習メニューの調整材料であり、
   気温1〜2度や局所的な降雨の差は提案内容を左右しない。市区町村単位の精度はMVPに対して
   過剰であり、選択肢の管理コスト(1900件超または2段階セレクト)に見合わない
2. 変換表をバックエンドに置くことで、プロバイダ差し替え時(ADR-012で天候APIは
   インターフェースとして抽象化済み)に影響範囲がOpenWeatherMap実装内に収まる
3. 「Ibaraki」「Ishikawa」がそれぞれ大阪府茨木市・沖縄県うるま市石川にヒットする問題は、
   ドキュメントを読むだけでは気づけず実測でしか分からない。同様の罠を踏まないよう、
   変換表はコード上のコメントとしても根拠(実測した座標)を残す

## 影響
- 設定画面の地域欄がセレクトボックスになり、ローマ字入力が不要になる
- `docs/database.md`の`users.region`の説明を更新
- 既存ユーザーの`region`(ローマ字)はそのまま動作し続ける。設定画面では現在の保存値を
  「(以前の設定)」付きの選択肢として表示し、都道府県を選び直して保存すると新方式に移行する
- サインアップ時の地域選択は追加していない(地域未設定でもAI提案は天候情報なしで生成される
  設計のため、docs/adr/012)
