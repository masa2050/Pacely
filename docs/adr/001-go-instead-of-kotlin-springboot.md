# ADR 001: バックエンド言語にGoを採用

## ステータス
決定済み

## 背景
Pacelyのバックエンド言語・フレームワークを決める必要があった。当初はKotlin + Spring Bootを想定していたが、就活での評価軸とMVP完成速度の観点から再検討した。

## 検討した選択肢
- **Kotlin + Spring Boot**: エンタープライズでの採用実績が豊富。ただし学習コストが高く(DI、アノテーション、Bean管理等)、個人開発でMVPを早く完成させるという目標とはトレードオフが大きい
- **Go**: アスクルのインターンで実務レベル(gRPC API検証ツールのバックエンド)を経験済み。文法がシンプルで学習コストが低い

## 決定
Go(Webフレームワークは軽量なEchoを採用)を選択する。

## 理由
1. インターンでの実務経験があり、就活の面接で「実務経験を個人開発に活かした」というストーリーを語れる
2. 志望している自社開発・SaaS企業・メガベンチャー群はGoの採用例が多く、対象企業層と噛み合っている
3. シンプルな言語仕様のため、個人開発でのMVP完成速度を優先でき、AI駆動開発(Claude Code)とも相性が良い(コード量が少なく読みやすいため、AIが書いたコードを理解しやすい)

## 影響
- Spring Bootで得られたであろうエンタープライズ的な設計パターンの学習機会は失うが、MVP完成という最優先目標には合致する
