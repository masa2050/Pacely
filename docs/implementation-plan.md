# Pacely 実装計画書

## 1. 進め方の方針

「1機能ごとにバックエンド+フロントエンドをセットで完成させる」方式で進める。各フェーズ完了時に以下を確認する。

- 何を作ったか
- なぜそうしたか
- どう動いているか
- 次に何をするか

1フェーズが大きくなりすぎないよう、フェーズ内でもさらに小さいタスクに区切ってClaude Codeに依頼する。

## 2. フェーズ一覧

### フェーズ0: 環境構築

- リポジトリ作成(GitHub)、CLAUDE.md配置
- Goプロジェクトの雛形作成(Echo導入、DB接続確認)
- Reactプロジェクトの雛形作成(Vite + TypeScript)
- ローカルでPostgreSQL(Docker)を起動し、BEからの接続確認
- Supabaseプロジェクト作成、Auth設定

**完了条件**: ローカルでBE・FEがそれぞれ起動し、疎通確認(ヘルスチェックAPI)ができる状態

### フェーズ1: 認証機能

- フロント: Supabase Auth SDKでサインアップ/ログイン画面を実装
- バック: JWT検証ミドルウェアを実装し、`GET /users/me`で動作確認
- DB: usersテーブル(拡張プロフィール用)作成

**完了条件**: ユーザー登録・ログインができ、ログイン後にJWTを使って`/users/me`が取得できる

### フェーズ2: ランニング記録機能

- DB: runsテーブル作成
- BE: `POST /runs`, `GET /runs`, `GET /runs/{id}`, `PUT /runs/{id}`, `DELETE /runs/{id}`実装(pace自動計算含む)
- FE: 記録入力フォーム、記録一覧画面

**完了条件**: ログイン後、記録の作成・一覧表示・編集・削除がUI上で一通りできる

### フェーズ3: 目標設定機能

- DB: goalsテーブル作成
- BE: `POST /goals`(active切り替えロジック含む), `GET /goals`, `GET /goals/active`, `PUT /goals/{id}`, `PATCH /goals/{id}/status`実装
- FE: 目標設定フォーム、現在の目標表示、目標履歴一覧

**完了条件**: 目標の新規作成・履歴確認・ステータス変更がUI上でできる

### フェーズ4: 進捗確認機能

- BE: `GET /goals/active/progress`実装(直近の記録から進捗を算出するロジック)
- FE: 進捗表示画面(現在ペース vs 目標ペースなど簡易表示)

**完了条件**: 現在の目標に対する進捗がダッシュボード的に確認できる

### フェーズ5: AI提案機能(コア機能)

- DB: advicesテーブル作成
- 外部API連携: OpenWeatherMap呼び出し処理、Claude API呼び出し処理をservice層に実装
- BE: `GET /advices/latest`(生成判定ロジック含む)、`GET /advices`実装
- FE: AIアドバイス表示画面、練習メニュー表示、履歴一覧

**完了条件**: 記録3件・目標ありの状態で`/advices/latest`を叩くと、AIによる提案が生成・表示される。24時間以内の再アクセスではキャッシュが返る

このフェーズは最も複雑なので、以下の順でさらに分割する:
1. Claude API呼び出しの疎通確認(固定プロンプトでの動作確認)
2. 天候API連携の疎通確認
3. 生成判定ロジック(3件未満・24時間以内のチェック)の実装
4. 全体を繋いだ`/advices/latest`の実装
5. フロント側の表示画面実装

### フェーズ6: 仕上げ・デプロイ

- regionプロフィール設定画面(天候取得用)
- 全体的なエラーハンドリング・バリデーションの見直し
- Vercel(FE)・Railway(BE)・Supabase(DB)への本番デプロイ
- AI APIの利用上限(spending limit)設定
- READMEの整備(セットアップ手順、技術選定理由、画面キャプチャ等)

**完了条件**: 本番URLでPacelyが実際に使える状態になっている

## 3. フェーズの依存関係

```
フェーズ0(環境構築)
   ↓
フェーズ1(認証) ← 全機能の前提
   ↓
フェーズ2(記録) ─┐
                  ├→ フェーズ4(進捗) ─┐
フェーズ3(目標) ─┘                    ├→ フェーズ5(AI提案)
                                       ┘
   ↓
フェーズ6(仕上げ・デプロイ)
```

フェーズ2・3はどちらを先にやっても良いが、AI提案(フェーズ5)は記録・目標の両方に依存するため、必ず後にする。

## 4. リスク・詰まりやすいポイント

- **フェーズ5(AI提案)が最も時間がかかる想定** — プロンプト設計の試行錯誤が発生するため、早めに着手して余裕を持たせる
- **JWT検証まわり**でSupabase Auth側の仕様理解に時間がかかる可能性がある → フェーズ1で疎通確認を最優先にする
- 天候APIの地域指定(都市名→緯度経度変換など)は事前にAPI仕様を確認しておく
